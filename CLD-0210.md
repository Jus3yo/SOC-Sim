# CLD-0210: Service account lockout: svc-backup@cloudora.io

Engagement: Cloudora · Shift 3 · 2026-08-27
Verdict: False positive · Severity (my rating): Informational (reported Medium)
QA review: Excellent

## Alert
Rule 'Account lockout (service account)' fired. svc-backup@cloudora.io locked out at 02:12 UTC after 12 failed sign-ins from 203.0.113.20 (LDN-SRV-BK1) between 01:55 and 02:11. The backup estate is mid-migration to the new storage array this week under change CHG-2102, with agent reconfiguration scheduled overnight.

## Hypothesis
Malicious: Attacker attempting brute-force or credential spray against the backup service account from an internal server.
Benign: Legitimate agent reconfiguration during the CHG-2102 storage migration window generating expected authentication failures due to cached or outdated credentials.


## Evidence checked
Morning handover confirms Change window CHG-2102 runs overnight Tuesday to Thursday (01:00 to 04:00 UTC) with service account authentication noise expected on the backup estate;
signin_week1.csv show 12 failed sign-ins (Error 50126) starting at 01:55:12 UTC leading to account lockout at 02:11:48 UTC;
Source host is internal backup server LDN-SRV-BK1 (203.0.113.20) acting strictly within the scheduled maintenance window.

## Action
Closed referencing CHG-2102. Noted for future account authentications during authorized storage migration windows cause noise.

## Justification
 CHG-2102 references a backup migration change window between 01:00 and 04:00 UTC. The alert window lasted between 01:55 and 02:11 UTC, which falls directly into the authorized change window. Authentication logs also indicate failures originated internally from LDN-SRV-BK1 (203.0.113.20) due to routine agent reconfiguration rather than malicious activity.
